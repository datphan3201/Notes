3. **Migration reconciliation (ISSUE-046):** complete remaining relation/settings mappings and broader acceptance beyond the verified local snapshot, exercise active attachment restoration and legacy MFA recovery, and rehearse managed backup/PITR. The importer retains unsupported fields/relations in the private raw archive; they are not silently presented as active product features. MFA recovery and any intentional product changes need a user-facing migration procedure. It never returns a cutover-ready report yet.
4. **Selected deployment/release acceptance (ISSUE-046/048):** trial the selected Render/Vercel/Supabase route with real projects and a stable frontend domain, including cold starts, cookies, private uploads, AI, worker sleep/recovery and HTTPS mail. The live backend remains local until that trial; Google Cloud/VPS provisioning stays deferred. Before production replacement, verify trusted proxy/rate limits, backup/restore, monitoring, large-data query plans and sustained worker/AI concurrency. A frontend production alias alone is not production acceptance.

No legacy issue is removed merely because a newer runtime has an alternative implementation. The production baseline still has its documented issues until cutover is verified. Subsequent milestones should close the specific gaps above with execution evidence, not remove assertions or mark them complete because source files exist.
